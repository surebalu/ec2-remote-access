# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**EC2 Remote Access**: a macOS Electron app that scans every AWS profile in `~/.aws` for EC2 instances and opens SSH (embedded xterm.js), SFTP, and RDP (embedded IronRDP web client) sessions to them. Connections go to AWS directly, either to a public IP or through **SSM Session Manager**; there is no relay service. See `README.md` for the user-facing feature list, install steps, and the routing table.

## Commands

```bash
pnpm install                 # pnpm 11 workspace; native builds gated by pnpm-workspace.yaml allowBuilds
pnpm dev                     # electron-vite dev with HMR (main/preload rebuild + renderer hot reload)
pnpm typecheck               # tsc -p tsconfig.node.json && tsc -p tsconfig.web.json (two separate projects)
pnpm test                    # node --test over tests/*.test.ts (runs .ts directly via --experimental-strip-types)
node --experimental-strip-types --test tests/transfers.test.ts   # a single test file
pnpm build                   # electron-vite build -> out/
pnpm test:ui                 # Electron smoke test of the built renderer with synthetic hosts; run after pnpm build
pnpm build:gateway           # electron-vite build + vite build -c vite.gateway.config.ts -> out/gateway/index.js
pnpm gateway -- --host 0.0.0.0 --port 8321   # run the headless gateway (serves out/renderer + WebSocket RPC)
pnpm build:native            # scripts/build-dictation.sh: the Swift dictation helper -> build/native/ec2ra-dictate (dist runs it)
pnpm dist                    # build + electron-builder DMG/zip for arm64 and x64 -> dist/
pnpm dist:arm64              # arm64 only (faster local packaging)
scripts/install-mac.sh       # install the dist/ build into /Applications and restart the app; detaches first, so it is safe from the app's own Terminal (Claude may be running there)
scripts/release.sh --bump patch [--publish]   # bump, typecheck, build; --publish uploads to S3 (needs UPDATE_URL, S3_URI)
scripts/deploy-pi.sh user@host   # build + install/update the headless gateway on an arm64 Linux box (systemd, tailscale serve); idempotent; ALLOW_TERMINALS=1|0 (unset keeps the machine's setting)
```

No linter is configured. `pnpm typecheck` is the gate `scripts/release.sh` runs before building; run it after touching `src/shared/` since both tsconfig projects include that directory.

Tests live in `tests/` and use Node's built-in runner with no transpile step, so test files import source as `../src/.../file.ts` (explicit `.ts` extension) and can only cover code with no Electron or DOM imports and no `@shared` path alias (type-only imports are fine): currently `src/shared/inventoryMerge.ts`, the Notes formatting commands `src/renderer/notesFormat.ts`, the browser rules `src/shared/browser.ts`, the terminal's `src/shared/termIntegration.ts` and `src/renderer/termLayout.ts`, the phone key-bar mapping `src/renderer/terminalKeys.ts`, the dictation helpers `src/shared/dictation.ts`, the rail sections' shortcuts `src/shared/keyCombos.ts`, the launcher's ranking and calculator `src/shared/launcher.ts`, the SFTP `safeTransfer`/`destinations` modules, the whiteboard geometry `src/renderer/boardGeometry.ts`, the browser's host spotting `src/shared/pageHosts.ts`, the Terminal ribbon's Git parsing `src/shared/gitStatus.ts` (`tests/gitStatus.test.ts` also checks it against a real `git` in a temp repo, with global config shut out), and the gateway server/host (`tests/gateway.test.ts` starts a real server on a random port and drives it with `ws`). `tests/ui-smoke.cjs` launches Electron against `out/renderer` with a stub preload (`tests/ui-preload.cjs`), blocks network requests, uses a temp app-data dir, and writes screenshots to a temp directory it prints. It never reads `~/.aws` or opens real sessions.

Dev-only env vars read in `src/main/index.ts`: `RDP_DEBUG_PORT` enables Chromium remote debugging when running under `pnpm dev`.

## Build layout and constraints

- **electron-vite** with three entries: `src/main` (ESM output), `src/preload` (CJS output, loaded as `out/preload/index.cjs`), `src/renderer` (React 19 + Tailwind 4 via `@tailwindcss/vite`).
- **Every runtime dependency is externalized** in `electron.vite.config.ts` (the whole `dependencies` list plus `cpu-features` and `electron-updater`), so main/preload never bundle node_modules. A new runtime dep must go in `dependencies`, not `devDependencies`, or the packaged app won't find it.
- `ssh2` is unpacked from asar (`asarUnpack` in `electron-builder.config.cjs`) and its optional native `cpu-features` build is disabled in `pnpm-workspace.yaml`. Keep it that way; `npmRebuild` is off.
- Path aliases: `@shared/*` → `src/shared/*` (all three entries), `@/*` → `src/renderer/*` (renderer only). Both tsconfigs mirror these.
- TypeScript 7 with `moduleResolution: Bundler`. `tsconfig.node.json` covers main + preload + shared + the vite config; `tsconfig.web.json` covers renderer + shared + `src/preload/index.d.ts`.
- Signing/notarization/auto-update switch on purely from env vars (`CSC_LINK`, `APPLE_ID`, `APPLE_TEAM_ID`, `UPDATE_URL`); with none set, `build/afterSign.cjs` ad-hoc signs and the updater stays inert.

## Architecture

### Host abstraction and the two front-ends

The connection engine in `src/main` never imports `electron` directly (only `index.ts`, `ipc.ts`, `electronHost.ts`, `updater.ts` do). Everything environment-specific goes through the `Host` interface in `src/main/host.ts`: `broadcast` (push events to UIs), `userDataDir`, `openExternal`, native pickers/questions, clipboard, theme, and `encrypt`/`decrypt` for saved passwords. Two implementations exist:

- `src/main/electronHost.ts`: real windows, native dialogs, `safeStorage`. Its `broadcast` and Quick Look target `mainWindow()` (`src/main/windows.ts`), since the launcher is a second window. Set by `index.ts` before anything else runs.
- `src/gateway/host.ts`: headless. Broadcasts go to WebSocket clients, pickers return null (callers treat as cancelled), questions return their `defaultId`, passwords are AES-GCM sealed with `gateway.key` in the data dir.

`src/main/handlers.ts` holds the complete `IpcApi` implementation as a plain object keyed by channel. `ipc.ts` registers each entry with `ipcMain`; `src/gateway/server.ts` dispatches WebSocket RPC to the same object. **Add new channels to `handlers.ts`, not to `ipc.ts`.** Any new Electron-only need goes on the `Host` interface with a gateway fallback.

`src/main/log.ts` mirrors `console.*` into `<host.logsDir()>/main.log` (5 MB rotation) and offers `log(scope, message, data)` for structured lines plus `recentLog()` behind the `diag:log` channel ("Copy diagnostics" in `RdpTab`). Both entries call `initLog` first thing. The RDP proxy (`rdp/cleanpath.ts`) logs each relay's open/close with byte counters, keeps TCP keepalive on the tunnel and the far socket, and runs a conservative 3-minute stall backstop (client input with zero server bytes) behind TCP keepalive, which is the primary dead-tunnel detector; keepalive-driven socket errors trigger IronRDP's reconnect; `dropConnections(token)` does the same when the tunnel's `session-manager-plugin` exits (`rdp/sessions.ts`). When a reconnect's `rdp:prepare` fails on an expired SSO token, `RdpTab` enters a `signin` phase (a Sign in button, `store.refreshToken()`) and resumes automatically once `store.authState()` returns `ok`, without consuming a retry attempt.

`src/main/store.ts` is a small atomic JSON store at `<userDataDir>/ec2-remote-access.json`, format-compatible with the electron-store file older versions wrote; it is lazy so the host can be set first.

### Gateway (`src/gateway`)

`server.ts` is a plain `node:http` server plus `ws`: serves `out/renderer` (rewriting the CSP `connect-src` so the browser may open same-origin WebSockets), `/ws?token=` for RPC (`{t:'call',id,channel,args}` / `{t:'result'|'error'}` / pushed `{t:'event',channel,payload}`), and `/rdp?token=` as a byte-transparent relay to the local RDCleanPath proxy (the `rdp:prepare` result's `proxyUrl` is rewritten to the gateway origin). It tracks sessions each socket opened (`ssh:open`, `sftp:open`, `rdp:prepare`) and closes them when the socket drops, refuses upgrades whose `Origin` host differs from the served host (`x-forwarded-host` wins behind `tailscale serve`), and reports connected client addresses through `onClientsChanged`. `index.ts` is the CLI: args/env, token file, data dir defaults (shares the desktop app's dir on macOS), shutdown. `vite.gateway.config.ts` bundles it in SSR mode with all dependencies external; the build must contain no `electron` import.

`src/main/phoneAccess.ts` hosts the same server inside the Electron app ("Phone access" in Settings): it reads `Settings.phoneAccess*`, binds per `phoneAccessBind` (`https` = loopback plus `tailscale serve` via `src/main/tailscale.ts`, which shells out to the Tailscale CLI for `status --json` and `serve`; `tailscale` = the CGNAT 100.64/10 address; `all` = every interface), shares the token file `<userData>/gateway.token` with the standalone gateway, and `electronHost.broadcast` mirrors every event to connected phones. It resolves `handlers` with a dynamic import because `handlers.ts` imports it for the `phone:*` channels. `PhoneAccessSection.tsx` renders the toggle, port, bind mode and a `qrcode` data-URL of the pairing link; it applies changes immediately and mirrors them into the Settings draft so Save cannot revert them.

**Phone layout.** `src/renderer/mobile.ts` decides once per page load whether to render `components/mobile/MobileApp.tsx` instead of the desktop shell (narrow or short touch viewport; never inside Electron; `?layout=` / `localStorage['ui.layout']` override). It is latched on purpose: the two shells mount `SessionPanes` in different places, so a live switch would remount and drop every session. `MobileApp` reuses the store, dialogs and session components; `TerminalTab` and `RdpTab` branch on `isMobile()` for a key bar (`mobile/KeyBar.tsx`, byte mapping in `terminalKeys.ts`) and bottom sheets (`mobile/Sheet.tsx`). The shell sizes itself from `visualViewport` (`--vv-h`, `data-keyboard`) because iOS overlays the keyboard instead of resizing. RDP touch and typing go through `src/renderer/rdpInput.ts`: `captureSessions` wraps the backend's `SessionBuilder` to keep each IronRDP `Session` and applies `DeviceEvent`s directly, since the web component exposes no input API and a canvas cannot raise the iOS keyboard (a hidden textarea does). On phones a style injected into the component's shadow root letterboxes the canvas in its pane, because the component otherwise sizes it from the window. Clipboard on phones (`mobile/ClipboardSheets.tsx`, `pasteFromClipboard` in `mobile.ts`): WebKit reads the clipboard only from a tap plus its own Paste bubble and writes it only from a tap, and xterm.js has no touch selection, so the key bar's paste key falls back to a paste box, Select text shows the scrollback in a read-only textarea, and RDP runs the component's clipboard in manual mode (`setEnableAutoClipboard(!mobile)`) with a tap-to-copy prompt; RDP paste types the text as Unicode key events. `index.html` has iOS web-app meta tags and `public/apple-touch-icon.png` but deliberately no manifest (a `start_url` would drop the `#token=` fragment). `tests/ui-smoke.cjs` runs a 430×932 `?layout=mobile` pass.

**iPhone and iPad app (`ios/`).** A universal SwiftUI app (`EC2Remote.xcodeproj`, file-system-synchronized group, so new Swift files need no project edits) that hosts the gateway UI in a WKWebView at `<gateway>/?layout=mobile&app=ios#token=…`. `Pairing.swift` parses the pairing link, checks `GET /auth`, and keeps computers in the Keychain; `WebView.swift` sends off-gateway navigation and `window.open` to Safari, turns downloads into a share sheet, implements JS alert/confirm/prompt, and removes WebKit's keyboard accessory bar. The page talks to it through `window.webkit.messageHandlers.ec2ra` (`nativeApp()` / `postNative()` in `mobile.ts`: `settings`, `sessions` count for the idle timer). Build check: `xcodebuild -project ios/EC2Remote.xcodeproj -scheme EC2Remote -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build`; install: `ios/install.sh`. `ios/archive.sh` archives with the paid team and uploads to App Store Connect/TestFlight (`INTERNAL_ONLY=1` locks the build to internal testers). `PrivacyInfo.xcprivacy` (UserDefaults, reason CA92.1) and `ITSAppUsesNonExemptEncryption = NO` are required for upload; add a privacy-manifest entry if the app starts using another required-reason API. `Device.name` gives "iPad"/"iPhone" for user-facing text; `QRScanner` follows device rotation through `AVCaptureDevice.RotationCoordinator`. `tests/ui-smoke.cjs` sweeps iPad portrait, landscape and Split View sizes. The iPad system shortcut bar over the soft keyboard is not suppressed (only the iPhone accessory bar is). `wsApi.ts` sends a per-page `client=` id so the gateway's `resumeGraceMs` (10 min) can return a backgrounded phone's sessions.

On the browser side `src/renderer/wsApi.ts` provides `window.api` when no preload did (see `main.tsx`), handling `clipboard:write`, `shell:open`, `theme:set` and `dialog:pickFile` locally and forwarding the rest. The renderer bundle is identical for Electron and the gateway.

### Process boundary and the IPC contract

`src/shared/ipc.ts` is the single source of truth for main ↔ renderer communication:

- `IpcApi`: request/response channels (`ipcRenderer.invoke`). Naming is `domain:verb` (`ssh:open`, `sftp:list`, `rdp:prepare`, `creds:get`, ...).
- `IpcEvents`: push channels main → renderer (`scan:progress`, `ssh:event`, `sftp:transfer`, `tunnels:changed`, `profiles:status`, `instances:updated`).

The preload (`src/preload/index.ts`) exposes exactly two typed functions on `window.api`: `invoke(channel, ...args)` and `on(channel, cb)` (returns an unsubscribe), plus `pathForFile` for Finder drops. The main side registers every handler in `src/main/ipc.ts` through a typed `handle()` wrapper that logs and rethrows errors, and pushes events with a `send()` helper that broadcasts to all windows.

**To add a channel**: declare it in `IpcApi`/`IpcEvents`, add the handler in `src/main/handlers.ts`, call it from the renderer via `window.api.invoke(...)`. Both front-ends pick it up automatically. Types in `src/shared/types.ts` are shared by both sides; the renderer never imports from `src/main`.

### Main process (`src/main`)

- `aws/`: `profiles.ts` parses `~/.aws/config` + `credentials`; `awsfiles.ts` does INI section read/write for those files; `credentials.ts` caches a per-profile SDK credential provider (SSO profiles resolve via `fromSSO`, static via `fromIni`, deliberately matching AWS CLI precedence, not the JS SDK default) and classifies auth errors into `login-required` vs `error`; `sso.ts` implements the IAM Identity Center device-code flow without the AWS CLI and writes a CLI-compatible token cache; `inventory.ts` scans EC2 + SSM `DescribeInstanceInformation` per profile/region and keeps the in-memory instance list (`findInstance(key)`); results are folded in through `src/shared/inventoryMerge.ts`, which keeps the last known hosts for a profile/region whose scan failed (marked `staleReason`/`lastSeenAt`, shown as a Cached badge) while a successful empty scan still removes vanished hosts; `inventory:scan` accepts `retryTargets` to rescan just the failed profile/regions; `passwords.ts` decrypts `GetPasswordData` with a local `.pem`.
- `store.ts`: `electron-store` with `settings` and `inventory` keys. `defaultSettings` is merged over stored settings on every `getSettings()`, so adding a setting means adding a default there and a field in `Settings`.
- `connect/route.ts`: `decideRoute(inst, force)` picks `ssm | direct | unreachable | not-running` from per-host overrides, the `preferDirect` setting, `ssmOnline`, and IPs. Also resolves default SSH/RDP user and identity file with precedence explicit > host override > account (`profileDefaults`) > global. All connect paths (SSH, SFTP, RDP, external terminal) funnel through this.
- `ssm/session.ts`: starts an SSM session with the SDK, then spawns `session-manager-plugin` with the same argv the AWS CLI uses and wraps its stdio in a `Duplex`. `startSshStream` (document `AWS-StartSSHSession`) feeds ssh2's `sock` option; `startPortForward` (`AWS-StartPortForwardingSession`) backs RDP tunnels.
- `ssh/session.ts` + `ssh/clients.ts`: ssh2 shell sessions keyed by session id, streaming to the renderer via `ssh:event`. `clients.ts` is a registry of live ssh2 clients so an SFTP tab can reuse an already-authenticated SSH connection to the same host/user (and vice versa) instead of logging in again. `ssh/persist.ts` (persistent shells, `Settings.persistentShells` / `HostOverride.persistentShell`, resolved by `persistentShell()` in `connect/route.ts`, never for Windows): `openShell` probes the host over a separate exec channel, then opens an exec-with-pty channel that creates and/or attaches the tab's tmux session (`ec2ra-<tab id>` on the private socket `-L ec2ra`, configured invisible: status, prefix and mouse off, no smcup so output lands in xterm scrollback) instead of `client.shell()`. The init command is sent only for a newly created shell. `ssh:close` with `endShell` (closing a tab) kills the session; every other close (reconnect, gateway grace expiry, quit) leaves it to resume. New tabs get `detached` (shells no tab shows) for the Resume/End banner. tmux (2.5+) drops output a slow client falls behind on (about eight screens queued, routine over SSM) and redraws only the last screen, so every attach sets tmux's title to `ec2ra:#{client_discarded}`; `DropWatch` spots the count rising in the output, and once output has paused for a second `refillScrollback` (session.ts) clears the tab and replays the gzipped `capture-pane` history, then `refresh-client` redraws the screen. A reconnect that resumes a shell without replaying its history gets the same refill. The tab's Sessions list (`ssh:listShells` / `ssh:switchShell`) moves the tab's tmux client with `switch-client` over a side exec channel instead of reconnecting; main clears the terminal and replays the target's `capture-pane` history (padded by a screenful so tmux's redraw does not erase it) before switching. Session names are the tmux user option `@ec2ra_label` (`labelCommand`, `cleanLabel`; `SshOpenRequest.shellLabel` names a tab's first shell, `ssh:renameShell` renames); the probe also reports each shell's foreground process through the pane tty's `tpgid` (`ps -o user:32= -o args=`, falling back for BSD ps) and its last screen line, which `components/Shells.tsx` (shared list for the popover and the phone sheet, plus the Resume banner) shows for unnamed ones. `showHostGrid` (Sessions list → All N sessions on one screen) sets `gridHost`, so `SessionPanes` tiles only that host's SSH tabs, and adds `transient` tabs (via `shellTab`) for the host's background shells; transient tabs are filtered out of the tab strip, ⌘K, the ⌘-number order and the phone lists, and `setActive`/`showGrid` drop them on leaving (unmounting detaches; `setActive` on one promotes it). Tile × closes persistent tabs with `detach`. `openShellTab` opens a shell in a new tab on the same connection (`shellName` + `shellHistory`, which replays its scrollback on attach); `duplicateTab` clears those so a duplicate gets a shell of its own. The Resume banner uses the same switch with `endPrevious` (no reconnect), and the Sessions/Detach controls show only while the tab is `connected`, since a reconnecting tab has no tmux client yet. `tests/persist.test.ts` covers the scripts; anything changed there should also be tried against a real tmux.
- `sftp/session.ts` + `localfs.ts`: SFTP browsing and a transfer queue (progress pushed via `sftp:transfer`), plus the local-filesystem half of the dual-pane Files tab. `sftp/safeTransfer.ts` writes every transfer to a temporary sibling and publishes it only on completion, refusing an existing destination unless the user chose Replace (Keep both / Skip / Replace conflict flow); `sftp/destinations.ts` provides the local and remote `TransferDestination` implementations. Remote Replace needs the OpenSSH `posix-rename` extension and fails without unlinking otherwise.
- `rdp/`: `cleanpath.ts` is a localhost WebSocket gateway implementing IronRDP's **RDCleanPath** handshake (X.224 forward, TLS to the target, hand the cert chain back, then relay bytes). `sessions.ts` (`prepareRdp`) resolves the route, opens an SSM port-forward if needed, registers a one-time token with the proxy, and returns a `ws://` URL the renderer's IronRDP component connects to. `launcher.ts` is the alternative hand-off to Microsoft Windows App via a generated `.rdp` file. `der.ts` is minimal ASN.1 DER helpers for the handshake.
- `tunnels.ts`: registry of SSM port-forward tunnels shown in the renderer's `TunnelBar`; broadcasts `tunnels:changed`.
- `portForward.ts` (`tunnels:open`): user port forwards over SSM, optionally to a `remoteHost` via `AWS-StartPortForwardingSessionToRemoteHost`; presets live in `Settings.portForwards`.
- `rdp/liveness.ts`: for SSM-routed RDP, the relay watchdog in `cleanpath.ts` probes the plugin's local port with a fresh X.224 request while the session is silent, because a dead SSM data channel leaves the plugin running and its listener answering TCP keepalive. Gated on agents that multiplex (`agentSupportsMux`); cuts only after two consecutive failures.
- `aws/health.ts` (`ec2:health`): status checks, scheduled events and CloudWatch CPU for the host details panel. `ssh/recorder.ts` writes ANSI-stripped transcripts when `Settings.sessionLogging` is on.
- `creds.ts`: per-instance RDP credentials encrypted with Electron `safeStorage` (Keychain-backed).
- `index.ts`: window creation, and a `before-quit` hook that closes all SSH/SFTP/RDP sessions and tunnels and stops the proxy before actually quitting. Any new long-lived resource type needs a `closeAll*` added there.

### Renderer (`src/renderer`)

- **Shell layout.** `AppRail.tsx` is the left column of sections (Hosts, Overview = `showGrid`, then the tool tabs Terminal/Browser/Notes/Whiteboard via `openTerminal`/`openBrowser`/`openNotes`/`openBoard`, each with a dot while its tab exists and a right-click Close; Shortcuts, theme and Settings at the bottom). Each item shows its shortcut under the label (`sectionKeyLabel` over `Settings.shortcuts`, so it follows Settings → Keyboard live), drawn by CSS from `data-keys` so the button's text stays its name, which text lookups and the smoke test match on; the rail's spacing is tight enough for a hint under every item in a 900-point window. `TerminalTabs` (the title-bar strip) shows only `isSession` tabs; tools are not in it. The hosts sidebar is hidden while a tool tab (browser, local, board, notes) is in front on its own (`browserInFront` in `App.tsx`); a note split beside a session keeps it. The title bar's brand segment is `--rail-w + --sidebar-w` wide (`data-sidebar="collapsed"` sets the sidebar to 0 and `Sidebar` renders nothing; ⌘B lives in `App.tsx` because the sidebar unmounts). `⌘,` opens Settings. Colours are tokens on `:root` (light) and the two dark blocks in `styles.css`; use `--accent`, `--panel`, `--border`, `--shadow*`, `--ease` rather than literals. `Modal` takes `bare` for dialogs with their own layout (Settings, Run Command).
- `SettingsDialog.tsx` is sectioned (`SECTIONS`: General, Accounts, SSH & RDP, Terminal, Notes, Phone & iPad, Requirements, About; last section in `localStorage['ui.settingsSection']`) with `Group`/`Row`/`Toggle` building blocks; a new setting goes into the section it belongs to. About reads `app:about` (version from package.json, data and log dirs) and `app:reveal` (desktop-only in the gateway).
- One zustand store, `store.ts` (`useStore`), holds all app state: profiles/statuses, instances, scan progress, tunnels, open `tabs` (kind `ssh | rdp | sftp | notes | browser | local | board`), filters, and which dialog is open. Actions that touch main live on the store and call `window.api.invoke`. `allInstances(state)` merges AWS instances with manual hosts.
- Pushed events only reach sockets that are open at that moment, so anything a phone must not miss needs a way to ask again. `refreshToken` (the SSO sign-in wait) polls `sso:sessions` every 3 s and decides through `src/shared/ssoWait.ts`, because the `profiles:status` "signed in" push is lost when iOS suspends the page and drops its socket while the user approves in Safari; `tests/ui-smoke.cjs` has the dropped-push scenario.
- The store's `init()` subscribes to `IpcEvents` (`window.api.on`) and maps them into state; `quickConnect.ts` holds the one-click openers (double-click → RDP for Windows, SSH otherwise) that skip the connect dialog when overrides/saved creds make the parameters known.
- `QuickSwitcher` (⌘K) searches hosts with `src/shared/hostSearch.ts` (`matchesHost` covers name, IPs, account, region, tags), lists recent successful connections and favorites first, and either opens a session via `quickConnect.ts` or switches to an already-open tab. `HostFilters` and `HostDetails` are the filter bar and the per-host inspector; `clearHostFilters` in `hostSearch.ts` is the patch applied when selecting a host that current filters would hide.
- Terminal appearance comes from `Settings.terminalTheme` / `terminalFont` / `terminalFontSize`, resolved by `src/renderer/terminalThemes.ts` (`TERMINAL_THEMES` catalog of xterm `ITheme` palettes; `'auto'` follows the app light/dark mode). `TerminalTab` applies changes to a live terminal through `term.options`, so a new scheme only needs an entry in the catalog. `TerminalAppearancePane` is the in-tab side pane (toggle persisted in localStorage as `terminalPaneOpen`); both it and `SettingsDialog` write the same settings, so changes propagate to every open tab. `Settings.sshInitCommand` (global) and `HostOverride.initCommand` (per host, `''` = disabled) are resolved by `defaultInitCommand` in `connect/route.ts` and written to the shell channel by `openShell` in `ssh/session.ts` as the session's first input.
- Session tabs: `TerminalTab` (xterm.js over `ssh:*`; on disconnect it keeps the buffer and offers Reconnect, which re-runs the same connect parameters, plus Edit connection), `SftpTab`, `RdpTab` (the `@devolutions/iron-remote-desktop` web component + wasm backend; wasm is initialized once, with auto-reconnect back-off and a fatal-error table for IronRDP error kinds). Every connection builds its own `<iron-remote-desktop>` (`mount`) and removes it when the session ends (`unmount`, which also `free()`s the captured wasm `Session` once `run()` has settled, never while it is pending): a flaky network means dozens of reconnects a day, and reusing one element let canvases and wasm framebuffers pile up until the renderer sat at gigabytes and 80% CPU. HiDPI (Retina) is opt-in for the same reason. `rdpTelemetry.ts` records JS heap, IronRDP wasm memory (its `memory` export is captured by wrapping `WebAssembly.instantiate*`, since `init()` returns nothing) and mount/connect/free counters, and "Copy diagnostics" prints them next to the main process's memory.
- `shortcuts.ts` owns app keyboard shortcuts (handled on `document`, ahead of the RDP client's window-level capture); `isAppShortcut` is also what `TerminalTab` tells xterm to ignore. The rail sections' own shortcuts (Settings → Keyboard) run first there, see *Claude, ChatGPT and section shortcuts* below. The Electron menu (`index.ts` `setMenu`) deliberately has no ⌘W so it can close tabs. **Side by side** (split view): `splitTree` in the store is a `PaneNode` tree of tab ids (the same `termLayout.ts` the Terminal tab uses, plus `insertPane`/`swapPanes`/`arrange`/`equalize`/`dockZone`), and `splitGroup` is always its panes in reading order (`splitFields` keeps them in step; a tree of one pane is no split). The group is on screen while the focused tab (activeTab) is in it; `splitWith(tab, other, side)`, `dockPane`, `unsplit`, `arrangeSplit`, `endSplit`, `focusPane` and `splitZoom` (⌘⇧↩) change it, and `addTab(tab, { beside })` / the `beside` argument of the `quickConnect.ts` openers / `connectFor.beside` open a new session into it. `SessionPanes` positions split panes absolutely from `layoutRects` (never moving them in the DOM: a terminal would lose its scrollback, a webview would reload) with a draggable `.tile-head` per pane; `SplitView.tsx` has the split bar (arrangements, find in all panes, Add, Done), the dividers and the dock shield. Dragging (a divider, a tab, a pane header, a rail tool) puts a shield over the panes, because webviews and the RDP canvas swallow mouse and drag events; HTML5 drags set `dockDrag` through `startDockDrag`. `paneFind.ts` is the window-event bus for "find in all panes" (`TerminalTab` and `BrowserTab` answer with counts) and for text handed between panes; `terminalAction(id, 'paste', text)` pastes into a terminal. The browser reads each page's text (`executeJavaScript`) and matches it against the inventory with `src/shared/pageHosts.ts` (unit-tested) for the *hosts on this page* pill; `App.tsx` pushes the terminals beside any page tab (Browser, Claude, ChatGPT) to main (`browser:paneTargets`, desktop-only in the gateway) so the page's context menu (`webviews.ts`) can offer *Paste into …*. Pages forward ⌘\, ⌥⌘ arrows and ⌘⇧↩. `broadcastInput` fans SSH input out to the group. The all-sessions grid is `gridView` (`showGrid`, ⌘0; `setActive` leaves it): `SessionPanes grid` lays the same pane elements out as tiles with a `.tile-head`, so switching never remounts a session; `activeTab` is the focused tile. `RdpTab tiled` fits the canvas into the tile (`data-contain` gates the shadow-root CSS) and skips `pushSize`. The fitted canvas box must equal the picture (absolute-centred, max-width/max-height, not object-fit), because the component maps clicks by scaling across the canvas box. On touch, a `.tile-shield` makes tiles open on tap. `Popover.tsx` is the shared anchored menu.
- zustand selectors must return stable values: `useStore((s) => s.x ?? [])` or `.filter(...)` inside a selector re-renders forever (React error #185). Use a module-level constant fallback, or select the raw value and derive outside.
- Manual (non-AWS) hosts are modelled as `Instance` objects via `src/shared/manual.ts` (`manualToInstance`, key `manual/<id>`, profile `servers`) so tables, routing and connect dialogs treat them uniformly; their connection settings live in `Settings.overrides[key]`.

### Terminal (local shells)

The `local` tab kind (`components/terminal/`, opened by `store.openTerminal`, or its section shortcut, ⌃` by default) is a Warp-like terminal for this Mac. `main/localterm.ts` runs the user's login shell in node-pty 1.1.0 (imported lazily so the gateway never loads it; its prebuilt `spawn-helper` lacks the execute bit, fixed at runtime and in `build/afterPack.cjs`; `node_modules/node-pty/**` is asar-unpacked; pnpm does not run its install script) and batches output into `term:event` every 5 ms. For zsh it sets `ZDOTDIR` to generated files in `<userData>/shell-integration/zsh` that source the user's `.zshenv`/`.zprofile`/`.zshrc`/`.zlogin` with ZDOTDIR swapped back, then add precmd/preexec hooks emitting OSC 133 A/C/D, 633;E (base64 command line), 633;P (Git branch, AWS profile) and OSC 7; `.zlogin` hands ZDOTDIR back. It sets `PROCESS_LAUNCHED_BY_Q=1` because Kiro CLI / Amazon Q otherwise re-exec the shell inside their own pty and the inner shell loses the hooks. `src/shared/termIntegration.ts` parses those sequences and the history file (unit-tested). `gateway/server.ts` `desktopOnly()` refuses the browser's fill/logins/downloads/share and the phone-access settings (`phone:configure`, `phone:rotateToken`, `phone:terminals`) from remote pages and never broadcasts web:* events; term:* calls are refused unless `GatewayOptions.allowTerminals()` (the Mac's `Settings.phoneTerminals`, only settable from its own window, and stripped from remote `settings:set`; the standalone gateway's `--allow-terminals`, set by `ALLOW_TERMINALS=1 scripts/deploy-pi.sh`). Even then `term:loadState`/`saveState` answer null for remote pages, `term:open` is tracked as the page's session (closed with it, and by `closeTerminals()` when the switch goes off), and a `term:event` goes only to the page that owns that id. On Linux node-pty has no prebuilt binary (the Pi installs with --ignore-scripts), so `localterm.ts` falls back to the API-identical `@lydell/node-pty`. `tests/gateway.test.ts` covers all of it. In the renderer, `TerminalApp` keeps `TerminalState` (layout presets from `presetLayout` via the grid button; tabs, shown down the side by default or across the top per `tabBar`, and across the top whenever the tab is under 560 px wide (a phone, a narrow split; measured, not `isMobile()`, so an iPad gets the side list), each a `PaneNode` tree from `termLayout.ts`, plus each pane's cwd; saved as terminal.json) and draws every pane of every tab absolutely from `layoutRects`, so splitting never remounts a pane (its xterm would lose its scrollback). `Pane` owns one xterm + pty (closing it on unmount), turns the OSC marks into blocks (xterm markers; gutter, separators, hover toolbar and sticky header are an overlay computed from marker lines each frame), and shows `InputDock` (the input box) only while zsh sits at its prompt with integration confirmed and no alternate screen; meanwhile xterm's stdin is disabled, a command is sent as one bracketed paste, Tab writes the line plus `\t` and leaves typing to the shell until the next prompt, and a running command gets the bar after 300 ms. Below it every pane ends in `Ribbon.tsx` (Warp's bottom bar, always shown, inside `.tpane-foot` with the dock or the phone key bar; on a phone it steps aside while the keyboard is up): new tab, a mic that dispatches `ec2ra:dictate` (`{ action: 'toggle', target: <.tpane> }`) and shows pressed while the last `ec2ra:dictation` had `active` (Electron only), the Git chip, Workflows (into the box, or pasted into the shell/program), History (a `DockRequest` to the box), Finder, and Rich input, which flips `TerminalState.input`; `⌃G` does the same only at the prompt (the box's textarea, or a capture handler on `.tpane-term` that keeps it from xterm), otherwise it is the program's. Labels fold to icons under 700 px through a container query, and the foot repaints `--term-backdrop` sized to the pane (`100cqh`) so a gradient scheme runs on behind it. Git data is `term:git` (`main/localgit.ts`: `git --no-optional-locks status --porcelain=v2 --branch -z` plus `diff --numstat -z HEAD`, 1.5 s timeout, parsed by `src/shared/gitStatus.ts`), asked by `useGitStatus` only where the prompt reported a branch, after each command, on a folder or branch change, when the pane shows and on window focus (debounced, one call at a time, never polled); the gateway gates it like every `term:*` channel. `setTabKeys('local', …)` in `shortcuts.ts` routes ⌘T/W/D/1…9/arrows to the Terminal tab while it is in front (the Browser uses the same mechanism); xterm ignores every ⌘ combination, ⌃Tab and the section shortcuts. `tests/ui-smoke.cjs` drives it against a fake zsh in the fixture that emits the same markers.

### Browser

An Arc-style browser in the `browser` tab kind (`components/browser/`). Pages are Electron `<webview>`s (`webviewTag` on the main window), created imperatively in `Webview.tsx` and never re-rendered: a new `src` would reload, so navigation uses `loadURL`, and `BrowserTab` renders them in mount order because React moving a keyed `<webview>` re-attaches (reloads) it. Webview methods throw before the first `dom-ready` and while a closed tab's page tears down, so every call goes through `safely`/`act`. Sidebar sections follow Arc: **Favorites** (`WebTab.favorite`, an icon grid per space: they use the space's partition, so showing them in other spaces signed a Personal space in as Work; `moveToSpace` keeps a favorite a favorite, and `initialState` gives a space whose saved selection is another space's tab its own most recent one), **Pinned** (`pinned`, per space) and **Today**. `⌘W` (`closeOrUnload`) unloads a favorite or pinned tab back to its `homeUrl` instead of closing it. `placeTab(id, target, where, zone)` is the one drag-and-drop move between the three. *Share…* goes through `browser:share` → `Host.shareUrl` (Electron `ShareMenu`; the gateway returns false). Fill from 1Password: `main/onepassword.ts` lists Login items through the 1Password CLI (`op`, found by `findBinary`, desktop-app integration; the list, no secrets, is cached until the panel's Reload or 12 h). 1Password ties an approval to a tty and an account, so every `op` call runs in one bash kept in a node-pty for the app's run (`runInTerminal`: a `r` function returns id, status, base64 stdout and stderr on one line; `closeOnePassword` on quit and after a timeout), so one approval per account lasts until 1Password's 10-minute idle limit; `loginMatches`/`siteOf` in `src/shared/browser.ts` match them to the page's site, and `browser:fill` reads the one item's secrets and calls `Host.fillWebPage` → `fillPage` in `webviews.ts`, which re-checks the guest's current URL and types the values in an isolated world; secrets never reach the renderer. Downloads are saved straight to `app.getPath('downloads')` (`freePath` avoids overwriting) and reported as `web:download` (progress, then the Finder icon); `browser:openDownload` only opens paths inside the Downloads folder. Zoom is one `BrowserState.zoom` applied to every page on attach/dom-ready (Chromium keeps zoom per site otherwise); the browser's own chrome (sidebar, start page, find bar, command bar) follows it through CSS `zoom: var(--web-zoom)`, clamped by `CHROME_ZOOM`, and the sidebar drag divides by it. Main reports mouse-downs inside pages (`before-mouse-event` → `web:pointer`) because the app's document never sees them, and that is what closes open menus; a webview's own `focus` event and the window's `blur` both fire when focus merely moves, so neither is used. ⌘1…⌘9 switch spaces in avatar order (⌃Tab cycles tabs in `sidebarOrder`); the sidebar width (`sidebarWidth`) is dragged on a shield over the pages, which swallow mouse events. A **space** is a partition `persist:web-<id>` (`partitionFor` in `src/shared/browser.ts`). Its look is a named `color`, or `custom: { from, to? }` (#rrggbb only, `isHexColor`, since it goes into a style attribute) applied through `spaceVars()` in `browser/parts.tsx` as the same `--c` / `--c-soft` / `--c-text` variables `[data-accent]` sets, plus `--c2` for a gradient (only then does `.browser` draw its fade down the sidebar), and an optional emoji `icon` that `SpaceAvatar` shows instead of the initials (AWS account spaces are derived, so their `custom` / `icon` live in `BrowserState.spaceLooks[spaceId]` and are merged into `awsSpaces`; their name and named colour follow `accountMeta`) (`lastGrapheme` keeps one emoji; `app:emojiPanel` → `Host.showEmojiPanel` opens the macOS picker, Mac app only). Anything that sets `data-accent={space.color}` should also take `style={spaceVars(space)}`; user spaces are stored, AWS spaces are derived from enabled non-static profiles (`aws-<profile>`, colour and label from `metaFor`). `main/webviews.ts` (Electron-only, called from `index.ts`) hardens every guest in `will-attach-webview` (no preload or Node, sandbox, only `persist:web-*` partitions and web URLs), denies permissions except clipboard writes and full screen, turns new windows into `web:window`, builds the page context menu (`web:menu` → today's note), reports downloads (`web:download`), and forwards browser shortcuts the page would swallow as `web:shortcut`. `BrowserTab` claims keys through `setBrowserKeys` in `shortcuts.ts` while it is the active tab and re-dispatches keys it does not use to `document` so app shortcuts still work from inside a page. `main/browser.ts` keeps `browser.json` (never with a federation link: `restorableUrl`) and implements `browser:consoleUrl`: the profile's temporary credentials → federation `getSigninToken` → a login URL for the destination. An AWS space federates on its first console page of the run and again whenever a page lands on the AWS sign-in page (`isAwsSignInPage`), with a 30 s loop guard per tab. The tab is desktop-only (`hasBrowser()` in `quickConnect.ts` gates entry points; elsewhere `openAccountConsole` / `openConsoleOnDevice` open a one-time console sign-in link in Safari, which the iOS app's WebView hands off-gateway navigation to), and the hosts sidebar is hidden while the browser is in front. Electron 44 logs `Invalid guestInstanceId` from its own code whenever a loaded webview is removed; the smoke test ignores exactly that message. `tests/ui-smoke.cjs` drives the browser against a local HTTP server, redirecting `*.console.aws.amazon.com` from the space partitions to it.

`launcher:quickLook` keeps the panel up behind Quick Look; `src/shared/launcher.ts` ranks (`matchScore`: whole, start, word start, initials, substring, letters in order; `usageBoost` for frequent and recent), calculates (a hand-written parser, never `eval`), converts units (`convert`: length, mass, temperature, data sizes decimal and binary, time, volume) and spots Jira issue keys (`issueKey`, with the site and space from Browser history by `jiraSite`). `main/system.ts` runs the Mac commands (`launcher:system`: a fixed table of programs and arguments; ### Health (3DEXPERIENCE platform)

The `health` tab kind (`components/health/HealthTab.tsx` + `parts.tsx`: sparklines, gauges, bars, pills; a rail section, ⌘K, the launcher, and a fourth tab-bar button on phones) shows the platform per environment from `health:snapshot` (`main/plmHealth.ts`, Electron-free so the gateway serves it to phones and iPads; not in `desktopOnly`). Main reaches the Prometheus server that monitors the platform through an SSM port forward to its private address via the monitoring host (`Settings.healthSource` { instanceKey, host, port }; default: a running SSM-online host named /monitor|prometheus/ and its private IP, port 9090). The tunnel is its own (`startPortForward` without `addTunnel`, so it stays out of the tunnel bar), closes ten minutes after the last read and on quit (`closePlmHealth` in both front-ends' shutdown), and is reopened once if a read fails. One snapshot runs about thirty instant queries plus four one-hour ranges and `/api/v1/alerts`, cached 20 s. CloudWatch (`@aws-sdk/client-cloudwatch`, `@aws-sdk/client-rds`) runs in the account that owns most of an environment's servers (inventory by private IP, preferring the monitor's VPC); the load balancers are found by resolving the public names the probes check (their CNAMEs are `<alb>-<n>.<region>.elb.amazonaws.com`, `albNameOf`) and `ListMetrics` for their dimensions and target groups; the database is the Oracle or SQL Server RDS instance whose identifier has the environment's token. Stopped EC2 instances are `off` everywhere and their alerts `muted`. Heap is judged by `min_over_time` over 15 minutes; `/boot` only counts as a server's fullest disk once it fills. The renderer polls every 30 s only while the tab is shown and the window visible, and keeps the last snapshot across closing the tab. `tests/ui-smoke.cjs` drives it against `healthFixture()` (or `HEALTH_SNAPSHOT_JSON`, a captured snapshot) on the desktop, a phone and a tablet.

The gateway refuses `finder:*`, `local:open` and `local:quickLook`.

### Colour themes

`Settings.colorTheme` ('' = the default look) picks an app-wide theme. `appThemeTokens.ts` (DOM-free, unit-tested in `tests/appThemes.test.ts`) computes every styles.css token from a terminal scheme's palette plus an accent from `ACCENTS`: surfaces mixed from the scheme's background and foreground, text colours pushed towards white or black only until they reach 7.5 / 4.8 / 3.2:1 on every surface (`readable`), `--on-accent` picked for contrast, and `--rail-backdrop` / `--panel-backdrop` gradients for schemes with a `backdrop` (Cyber Wave). `appThemes.ts` builds `APP_THEMES` from `TERMINAL_THEMES` and `applyColorTheme` sets the tokens inline on `<html>` (they beat the stylesheet's `:root` blocks) with `data-color-theme`. `store.applyAppearance(theme, colorTheme)` applies both and forces `data-theme` to the theme's light/dark so `isDarkMode()` agrees; `setTheme` (Auto/Light/Dark) clears the colour theme, `setColorTheme` sets it and sends `theme:set` so native controls match; both also set `terminalTheme: 'auto'`, because the terminal is expected to follow the main theme. Terminals resolve their scheme through `effectiveScheme(terminalTheme, colorTheme)`: "Match app" (`'auto'`) takes the colour theme's scheme. Anything else that changes the main theme must save `terminalTheme: 'auto'` with it (and the Settings draft must mirror it, or Save writes the old scheme back). Hard-coded white text on accent backgrounds should use `var(--on-accent)`; a new token in styles.css must also be produced by `tokensFor`.

### Text size per section

`Settings.sectionZoom` (`renderer/sectionZoom.ts`, steps 75–140%) scales the hosts sidebar and the hosts list separately through CSS `zoom: var(--zoom-sidebar|--zoom-hosts)`. The sidebar divides its width by its zoom so it keeps its place on screen. ⌘+ / ⌘− with the pointer over a `[data-zoom-section]` element zoom that section (handled in `App.tsx` before `handleAppShortcut`, so the View menu's whole-window zoom only applies elsewhere; ⌘0 stays the grid); `ZoomControls.tsx` has the stepper (sidebar footer "Aa" popover, Settings → General) and the size badge. Anything positioned `fixed` from mouse coordinates inside a zoomed section must be portalled to `document.body` (the hosts table's context menu is), because zoom scales fixed offsets too.

### App font

`Settings.uiFont` (default Monaco) picks the interface font from `UI_FONTS` in `renderer/uiFont.ts`; `applyUiFont` sets `--ui-font` and `--mono-font` on `<html>` (a monospace choice is used for both) plus `data-ui-font-mono`, which widens the sidebar and search field. Every font in styles.css goes through those two variables, and Tailwind's `--font-sans` / `--font-mono` point at them, so a new rule should use `var(--ui-font)` or `var(--mono-font)` rather than a font stack. Notes (`--notes-font`) and terminals (`terminalFont`) have their own settings. The whiteboard draws text with `var(--ui-font)` and measures it on a canvas with `uiFontStack()`, since a canvas cannot read CSS variables; `exportPng` writes the stack into the SVG.

### Run Command and the menu bar

`main/aws/runCommand.ts` (channels `run:*`) sends one command with SSM `SendCommand` to every chosen host that is running with an online agent (`AWS-RunShellScript` on Linux, `AWS-RunPowerShellScript` on Windows), batched 50 per account/region/OS, then polls `GetCommandInvocation` every 2 s until each invocation ends (an `InvocationDoesNotExist` right after sending means "not yet"), with a deadline of the timeout plus 3 minutes. Runs stay in memory (last 20). The renderer polls `run:status` rather than listening for events, so a phone that slept still gets results. `RunCommandDialog.tsx` (`store.runCommandFor = { keys, runId? }`) composes and shows results; entry points are the hosts toolbar (filtered rows), group headers, the host menu and details, ⌘K, and the phone's More and host sheet. Production accounts (label or profile matching /prod/) or more than ten hosts ask with `window.confirm` first.

`main/tray.ts` (Electron only, macOS) is the menu-bar icon (`Settings.menuBarIcon`, default on): favorites from settings and the cached inventory, Find a Host, Rescan, Quit; the menu is built when it opens. It sends `app:command` straight to the window's webContents, never through `host.broadcast` (that would reach phones); `App.tsx` handles it. `registerIpc(onSettingsSaved)` calls `updateTray` after `settings:set`. The icon is `resources/trayTemplate(@2x).png`, drawn by `scripts/make-tray-icon.mjs` and shipped via `extraResources`. `AuthBanner` also posts a macOS notification for an expiring or expired sign-in while the window is unfocused (skipped when notification permission is denied, which the smoke test does so nothing reaches the desktop).

### Voice dictation

Talk wherever you type (Mac app only; `CAN_DICTATE` in `src/renderer/voice.ts` is false in the gateway and phone layout). Recognition is a native helper, `native/dictation/main.swift` → `build/native/ec2ra-dictate` (`scripts/build-dictation.sh`: universal, macOS 12, Info.plist embedded with `-sectcreate`; shipped by `extraResources` to `Resources/dictation`, ad-hoc signed in `build/afterSign.cjs`), around `SFSpeechRecognizer` with `requiresOnDeviceRecognition` when the language supports it: JSON lines on stdout (`ready`/`partial`/`final`/`level`/`error`), `stop`/`cancel` on stdin. `--status` reports permissions **without asking for any**, and is the only way to run it outside the app (no prompt may reach the desktop). Chromium's Web Speech API has no recognizer in Electron, and a cloud service would break the About page's privacy promise. `src/main/voice.ts` (channels `voice:*`) runs one helper at a time and sends `voice:event` through `host().voice.send` to the Mac's own windows, never `host.broadcast` (phones would hear the Mac); `host().voice` is the Electron-only part (`helperPath`, `askForMediaAccess`, opening the Privacy panes) and is null on the gateway, whose `desktopOnly()` also refuses `voice:*`. `voice:key` carries the dictation key out of browser pages (`webviews.ts` `before-input-event`). In the renderer `voice.ts` resolves the target (the focused or last-focused editable; a registered ancestor wins over a text field inside it, which keeps xterm's helper textarea out), writes partials live into `<input>`/`<textarea>` (native value setter + input event, kept out of undo) and the final text with `execCommand('insertText')`, and fits spacing and case with `fitDictation` (`src/shared/dictation.ts`, unit-tested with the line parser and `HoldToTalk`). Non-field targets call `registerDictationTarget(el, …)`: `codeMirrorTarget` (Notes, live, one undo step), `xtermTarget` (`TerminalTab`, `terminal/Pane.tsx`: final text via `term.paste`, no Enter), `RdpTab` (Unicode keys via `RdpInput.text`) and `Webview.tsx` (`insertText`). Triggers: the hold key (`Settings.dictationKey`, default Right Option, alone for 200 ms; any other key or a click first makes it a modifier again), Esc to cancel (window capture phase, ahead of Modal and Popover), and mic buttons (`MicButton.tsx`) speaking the window-event contract `ec2ra:dictate` `{ action: 'toggle'|'start'|'stop'|'cancel', target? }` / `ec2ra:dictation` `{ active }`; buttons keep the focus with `onMouseDown` preventDefault. `VoiceHud.tsx` is the pill; Settings → Voice reads `voice:status`. `tests/ui-smoke.cjs` drives it all against a scripted fixture helper.

### Identity keys

An instance's `key` is `${profile}/${region}/${instanceId}` (or `manual/<id>`). It indexes `Settings.overrides`, `favorites`, saved credentials, and every IPC call that names a host. Don't use `instanceId` alone; the same instance can appear under two profiles.

## Conventions worth knowing

- Comments in the code explain *why* a non-obvious choice was made (CLI-vs-SDK credential precedence, why ssh2 is externalized, IronRDP error kinds). Keep that style; skip comments that restate the code.
- Errors thrown from main handlers reject the renderer's `invoke` and are shown via `toast('error', ...)` by the calling action; throw `Error` with a user-readable message (see the `session-manager-plugin not found` message in `ssm/session.ts` for the tone).
- The special error message `'cancelled'` is treated as expected by the IPC wrapper (a superseded in-flight connect) and is not logged.
- `scripts/install-ssm-agent.sh` is an ops helper for onboarding private RHEL hosts onto SSM through a bastion; it is unrelated to the app build.
